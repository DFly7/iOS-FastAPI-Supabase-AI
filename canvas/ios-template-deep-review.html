Issues Worth Fixing
Mixed Observability Pattern
AuthService is ObservableObject + @StateObject in the App entry point, while ContentViewModel uses the modern @Observable + @State. These two patterns coexist — not a bug, but a template should be consistent so users know which to follow for new services.
Recommendation
Migrate AuthService to @Observable and use @State in the App entry point. Consistent pattern across the template removes the decision fatigue for users adding their own services.
ContentView is Overloaded
At 317 lines, ContentView.swift combines three demo domains (JWT test, profile CRUD, notes CRUD) with ErrorBanner, avatar helpers, and composer state. It demonstrates the pattern well but would be hard to clean up vs. follow.
Recommendation
Split into Views/JWTTestView.swift, Views/ProfileView.swift, Views/NotesView.swift. Move ErrorBanner to Views/Components/ErrorBanner.swift. Demonstrate the per-feature view + viewmodel pairing users will actually replicate.
URLSession.shared in BackendAPIService
AuthService creates a custom URLSession with 60s timeouts and waitsForConnectivity: true. BackendAPIService uses URLSession.shared — different timeout behaviour and no connectivity waiting. On a bad connection the backend calls may fail while Supabase calls succeed.
Hardcoded Test Bundle IDs
Project.swift has bundleId: "com.example.StarterAppTests" and "com.example.StarterAppUITests" hardcoded, while the main target uses the xcconfig-driven $(PRODUCT_BUNDLE_IDENTIFIER). When a user renames their app, test targets stay on com.example.*.

Why This Matters for AgentX
Without .cursor/rules/ios.mdc, agents will try to edit StarterApp.xcodeproj/project.pbxproj to add files instead of just creating Swift files. They'll edit GeneratedModels.swift instead of running make sync-models. They'll create ObservableObject services instead of @Observable ones. These aren't hypothetical — they're exactly what LLMs do without explicit guidance. The 30 minutes to write three rule files pays dividends on every agentic task.
